## Méthode

1. **Lecture du CSS** : `postcss` lit chaque `src/**/*.css`. Chaque règle est découpée par sélecteur
   (virgules de premier niveau), avec fichier, ligne de début et de fin, et contexte `@media` / `@supports`.
   Les classes sont extraites par un petit analyseur de sélecteurs : `:not()` ne compte pas comme une
   classe exigée, `:is()` / `:where()` / `:has()` comptent comme un choix (vivante si une alternative l'est).
2. **Où on cherche les usages** : `src/**/*.{js,jsx}` hors tests, `index.html`, `public/**/*.{html,js}`
   (166 fichiers ; 84 fichiers de test). Les commentaires sont retirés par un vrai parcours caractère par caractère (voir
   « Faux positifs » : la première version, à base d'expressions régulières, se trompait). Les tests
   (`src/**/__tests__`, `src/test`, `e2e/`) sont comptés à part.
3. **Mot entier** : un nom composé (avec un tiret, `rv-card--big`) est trouvé n'importe où dans le code
   avec des frontières `début / espace / guillemet / backtick / ${ / } / . / ( …`. Un nom d'un seul mot
   (`card`, `active`) doit en plus se trouver **dans une chaîne**, sinon c'est un identifiant JS
   (`const card`) : il est alors classé « douteux, identifiant nu ». Les noms courts (≤ 4 lettres) ou
   génériques non trouvés sont aussi « douteux ». (Dans cette base : aucun cas, tous les noms d'un seul
   mot sont soit utilisés, soit absents partout.)
4. **Classes fabriquées** : une chaîne de gabarit `` `xx-${…}` ``, ` xx${…}`, une concaténation `'xx-' + …` ou
   un suffixe `${…}-xx` / `+ '-xx'` rend « douteuse » toute classe qui commence (ou finit) pareil. Le
   script en a trouvé 277 préfixes et 32 suffixes (tableau en annexe). C'est volontairement large : mieux
   vaut une fausse douteuse qu'une fausse morte. Les sélecteurs d'attribut `[class*=…]` sont traités de
   même (il n'y en a aucun).
5. **Règle morte sûre** : tous ses sélecteurs exigent au moins une classe morte sûre. Un `@media` dont
   toutes les règles sont mortes est compté en entier. **Règle douteuse** : pas morte, mais chaque
   sélecteur exige une classe morte ou douteuse (elle serait morte si les douteuses l'étaient).
6. **Fichiers orphelins** : graphe d'imports depuis `src/main.jsx` (imports statiques, `import()` des
   routes paresseuses, `@import` de `global.css`). Un CSS hors de ce graphe n'est jamais chargé.
7. **Ordre de chargement** (pour dire qui gagne un conflit) : les CSS importés statiquement partent dans
   l'ordre de l'import (`global.css` avec ses 12 `@import`, puis `desktop.css`, puis ceux de `App.jsx` et
   des composants chargés d'emblée) ; ceux des routes paresseuses sont ajoutés plus tard, donc gagnent.
   Entre deux CSS paresseux, l'ordre dépend de la navigation, sauf s'ils sont toujours chargés ensemble.
8. **Variables** `--x` : déclarée = propriété `--x:` dans le CSS ; lue = `var(--x` dans le CSS, le JS ou
   le HTML (ou `getPropertyValue('--x')`) ; écrite par le JS = clé `'--x':` d'un `style={{}}` ou
   `setProperty('--x'`. Les lectures faites dans les fichiers orphelins ne comptent pas.
9. **Conflits** : même sélecteur exact (espaces normalisés, même `@media`) dans deux fichiers différents,
   même propriété, valeurs différentes (`!important` pris en compte). En plus : les doublons internes à un
   fichier, et les « surcharges » (même sélecteur à `html:not(.native)` ou `@media` près).

**Limites connues** : classes fabriquées d'une manière que les motifs ne voient pas (`'a' + 'b'`
séparés dans deux fichiers) ; classes posées par une bibliothèque tierce (aucune détectée : pas de
`react-transition-group`, etc.) ; données non-JS chargées à l'exécution (le contrôle croisé ci-dessous
couvre aussi les JSON de `src/` et `public/`) ; composants importés mais jamais rendus, comme le défaut
de `SocialLogin.jsx` (voir Constats) : leurs classes comptent comme utilisées.
